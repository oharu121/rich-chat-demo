# Dev Notes: 2026-01-05

## Fix: Travel Context Persists Incorrectly Across Sessions

### Problem

When using the travel agent, the questionnaire (asking about duration, budget, interests) was being skipped for new trips because context from previous sessions was persisted in `localStorage` and automatically sent to the backend.

**Example:**
1. User plans trip to Japan, fills out questionnaire
2. Closes browser
3. Opens browser, asks about trip to Brazil
4. **Bug**: Questionnaire skipped - uses old Japan trip preferences for Brazil

### Root Cause

Two Zustand stores were using `localStorage` persistence:

```typescript
// agentContext.ts - Agent-specific context (destination, budget, etc.)
export const useAgentContextStore = create<AgentContextState>()(
  persist(
    (set, get) => ({ ... }),
    { name: "agent-context-storage" }  // localStorage
  )
);

// chatStore.ts - Chat messages
export const useChatStore = create<ChatState>()(
  persist(
    (set) => ({ ... }),
    { name: "chat-storage" }  // localStorage
  )
);
```

### Industry Standard Research

Researched best practices for chatbot state persistence:

| Data Type | Recommended Storage | Rationale |
|-----------|---------------------|-----------|
| User preferences (dark mode, language) | localStorage | Should survive browser restart |
| Chat history | sessionStorage or server-side | Session-scoped, fresh-start for new sessions |
| Conversation context | In-memory or sessionStorage | Session-specific, stale data is harmful |

**Key insight from [Predictable Dialogs](https://predictabledialogs.com/learn/ai-stack/session-persistence-ai-chat-continuity-strategies):**
- Enable persistence for complex multi-step workflows *within a session*
- Use fresh starts for independent interactions where previous context adds no value

**Trip planning is inherently fresh-start** - each trip is different, old preferences (duration, budget for Japan) don't apply to a new destination (Brazil).

### Solution

**1. Agent context store** - Removed persistence entirely (in-memory only)

```typescript
// Before
export const useAgentContextStore = create<AgentContextState>()(
  persist(
    (set, get) => ({ ... }),
    { name: "agent-context-storage", ... }
  )
);

// After
export const useAgentContextStore = create<AgentContextState>()((set, get) => ({
  // Same implementation, no persist wrapper
}));
```

**2. Chat store** - Switched from localStorage to sessionStorage

```typescript
// Before
{ name: "chat-storage" }

// After
{
  name: "chat-storage",
  storage: createJSONStorage(() => sessionStorage),
}
```

### Behavior After Fix

| Storage | Before | After |
|---------|--------|-------|
| Agent context | localStorage (permanent) | In-memory (clears on refresh) |
| Chat messages | localStorage (permanent) | sessionStorage (clears on browser close) |

**User experience:**
- Page refresh: Chat history preserved, agent context preserved
- Browser close/reopen: Both cleared, fresh start
- New trip (e.g., Brazil after Japan): Questionnaire always shown

### Files Changed

| File | Change |
|------|--------|
| `frontend/stores/agentContext.ts` | Removed `persist` middleware |
| `frontend/stores/chatStore.ts` | Changed to `sessionStorage` |
| `.issues/travel-context-persists-incorrectly.md` | Marked as fixed |

### Why Not localStorage for Chat?

Considered keeping localStorage for chat history but decided against it:

1. **Privacy** - Users expect chat to be ephemeral
2. **Storage bloat** - Messages accumulate indefinitely
3. **Stale context** - Old conversations can confuse the user
4. **Industry norm** - Most chat apps don't persist across browser sessions unless logged in

For future: If we add user accounts, consider server-side persistence with explicit "load previous conversation" UX.
