# Dev Notes - 2026-01-14

## Topic: Keeping Hugging Face Space Alive

### Current Setup
Using Google Apps Script to ping the HF Space endpoint every ~10 minutes:

```javascript
function keepAlive() {
  const url = "https://oharu121-rich-chat-demo.hf.space/healthz";
  const response = UrlFetchApp.fetch(url);
  Logger.log(response.getContentText());
}
```

### GitHub Actions as Alternative?

GitHub Actions supports cron-based scheduled workflows. Example workflow:

```yaml
name: Keep HF Space Alive

on:
  schedule:
    - cron: '*/10 * * * *'  # Every 10 minutes
  workflow_dispatch:

jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: Ping HF Space
        run: |
          curl -s https://oharu121-rich-chat-demo.hf.space/healthz
```

#### Comparison

| Factor | Google Apps Script | GitHub Actions |
|--------|-------------------|----------------|
| Reliability | Very consistent | Can skip/delay runs during load |
| Min interval | 1 minute | ~5 minutes practical |
| Free quota | 90 min/day runtime | 2,000 min/month |
| Auto-disable | No | Yes, after 60 days repo inactivity |

#### GitHub Actions Auto-Disable
- Scheduled workflows are disabled after 60 days of repository inactivity
- Dependabot PRs/commits count as activity and prevent this
- Other activity: commits, pushes, PRs, issues, manual workflow runs, releases

### Recommendation
**Stick with Google Apps Script** - already working, more reliable, no auto-disable risk.

## Hugging Face Spaces Sleep Timeout

### Key Finding
For free `cpu-basic` hardware: **48 hours** of inactivity before sleep.

### Implication
Current 10-minute ping interval is overkill. Could safely use:
- 24 hours (very safe)
- 36 hours (safe)
- 45 hours (cutting it close)

### Google Apps Script Quotas
- Based on **execution time**, not call count
- Daily quota: 90 minutes runtime (free Gmail)
- Each ping: ~1-2 seconds
- 144 pings/day (every 10 min) = ~3-5 minutes total runtime
- **No practical quota concern** with current setup

### Conclusion
No urgent need to change the current setup. If desired, frequency could be reduced to once daily for cleaner logs, but the current setup works fine.
